## [Unreleased]

### Fixed (2026-11 full recheck — firmware 1.2.0)
The firmware has never run on WellD hardware; these were found by checking the code against the TI ADS1115 datasheet, the esp-zigbee-sdk v2.0.1 examples/headers and library disassembly, and the ds18b20 0.3.1 driver source.
- **The Zigbee stack aborted on start-up**: esp-zigbee-lib 2.x keeps its network datasets in an NVS partition (`zb_storage` by default) and calls `abort()` if it cannot open it — the partition table had none and nothing initialised it. Added `zb_storage` (16 KB, in the unused gap before `ota_0` — **reflash the partition table over serial once**), initialised in `app_main` and passed as `storage_partition_name`; if it is unavailable the wakeup skips the send instead of crash-looping.
- **Every ADS1115 read failed**: the data-rate bits were OR-ed into the config MSB — rewriting the AIN0 mux to AIN2 and leaving the LSB at 8 SPS (125 ms per conversion against a 10 ms timeout) — and the conversion-ready setup wrote the threshold registers' *reset* values (Lo 0x8000 / Hi 0x7FFF) instead of Hi MSB = 1 / Lo MSB = 0, so ALERT/RDY never asserted. DR now sits in the LSB, Hi_thresh = 0x8000 / Lo_thresh = 0x0000, and every conversion is confirmed via the OS bit (DRDY accelerates, polling is the fallback).
- **Settle times and timeouts were tick-quantised away** (`CONFIG_FREERTOS_HZ=100`): the 1 ms battery-divider settle was no delay at all, the "≥ 10 ms" VLOOP settle was 0–10 ms, and the 10 ms conversion timeout could expire almost immediately. They now use `esp_rom_delay_us()` or round-up-plus-one-tick waits.
- **The > 21 mA short-circuit check could never fire**: AIN0's ±2.048 V range clips at 20.47 mA. Both channels now use ±4.096 V; the shunt Kconfig range is 1–130 Ω (was 155 Ω, sized for the long-gone ESP32 internal ADC).
- **DS18B20**: the resolution Kconfig value (a bit count, 11) was passed as the driver's 0–3 enum index — an out-of-bounds table read — and the firmware slept 375 ms on top of `ds18b20_trigger_temperature_conversion_for_all()`'s fixed 800 ms. The enum is now mapped and the per-device trigger's own wait (400 ms at 11-bit) is the only delay: ~0.8 s less awake time per wakeup.
- **OTA could never succeed**: esp-zigbee-lib 2.x hands the OTA client the raw `.zigbee` file and the firmware wrote it to flash verbatim, which `esp_ota_write()` rejects at the first byte. New host-tested streaming parser `welld_ota_parser_*` (welld_core) forwards only the Upgrade Image element; stages follow the SDK 2.0.1 contract (CHECK → APPLY → FINISH reboots), and `esp_ota_begin()` erases only the file size.
- **OTA was unreachable**: a sleepy device only sees an Image Notify if it polls its parent at the right moment, so it now sends Query Next Image on every wakeup — Zigbee2MQTT serves the file on the first query after an update is requested.
- **The OTA "stall" timeout capped the whole download at 240 s**, so any real ~650 KB transfer (many minutes) would have been aborted. It now measures time since the last block.
- **CI never produced a `.zigbee` file**: the workflow searched `$IDF_PATH` for `ota_image_create.py`, which ships with neither ESP-IDF nor the managed component, and skipped with a warning on every run. Added `tools/ota_image_create.py` (stdlib Python, the same layout as esp-zigbee-sdk's `image_builder_tool`); CI reads the manufacturer code / image type from `zigbee.c`, packs every build and fails if it cannot.
- **The stack was torn down from inside its own callbacks**: esp-zigbee-lib 2.x's mainloop only returns on a `select()` failure, and `esp_zigbee_deinit()` from a callback freed the task queue, lock and radio workflow while still in use — at best every wakeup then hung the full 5 s waiting for `STOPPED_BIT`. The stack is now parked under its lock (`esp_zigbee_lock_acquire()`) and the device deep-sleeps, as the SDK's deep-sleep example does. `STOPPED_BIT` is gone.
- **Steering ran on every wakeup**, including when already on a network (for an on-network node BDB steering is the "open the network for joining" procedure). It now runs only when factory-new; otherwise the reports go out right after `DEVICE_REBOOT`.
- **The factory reset did not re-pair**: the network state lives in `zb_storage`, which it never erased. It now erases NVS and `zb_storage`, logs `FACTORY_RESET`, and re-stamps the proven-image marker so waiting for permit-join cannot trigger an OTA rollback.
- I²C bus recovery sampled SDA with its input buffer disabled (always 0), so every wakeup logged "SDA stuck LOW" and clocked recovery pulses; the pins are now `INPUT_OUTPUT_OD`.
- `sdkconfig.defaults.local` was silently ignored — ESP-IDF reads only `sdkconfig.defaults` unless told otherwise — including the secure-boot signing switch the docs put there. The root `CMakeLists.txt` now appends it to `SDKCONFIG_DEFAULTS` (regenerate with `idf.py set-target esp32c6` after editing).
- Diagnostic mode did not compile (`%u` with `uint32_t`, a `-Werror=format` error). A new CI build-variant matrix compiles every non-default Kconfig path.
- A wakeup aborted by an I²C init failure dropped its sleep from the rate-of-change window; RTC-log timestamps restarted at 0 on every wakeup (now the RTC-backed `time()`: seconds since cold boot).

### Changed (2026-11 — firmware 1.2.0)
- **Automatic 5-failure NVS wipe removed** (user decision). It never touched the Zigbee join state, and making it do so would orphan the device after any coordinator outage longer than ~25 min; the stack's own rejoin handles outages, and the GPIO23 factory reset is the manual re-pair path. `zb_fails` (EP5) is telemetry only; `welld_should_wipe_nvs()` is removed.
- **Failure backoff** (user decision): from 3 consecutive failed sends the device sleeps `CONFIG_WELLD_SLEEP_MAX_SEC` (default 30 min) between attempts until one succeeds. A failed wakeup keeps the radio searching for up to ~25 s, so retrying every 5 min drained an 18650 in ~2–3 weeks of coordinator outage. New pure helper `welld_fail_backoff_sleep_sec()`.
- Removed the dead `CONFIG_WELLD_SENSOR_ADC_CHANNEL` option (there is no internal-ADC code path) and the unused `esp_adc` dependency; README's dev-board notes now describe an ADS1115 breakout (`docs/wiring.md` still needs a full rewrite — it carries a warning banner).
- Docs: TROUBLESHOOTING's 2S-era `< 6.00 V` low-battery log line, README's D9/D10 TVS part (SMAJ5.0A since 2026-07-14), C34/C35 refdes and the shunt-bypass corner (~160 kHz, not 1.6 MHz) corrected.

### Hardware
- **USB-C console/programming enabled** (user decision): the USB-C data lines — previously dead-ended at the USBLC6 ESD clamp (power-only port) — are routed through to the ESP32's native USB pins (U11.6→GPIO12 D−, U11.4→GPIO13 D+), so the same USB-C used for charging now also provides serial console, programming, and USB-DFU. To free the native USB pins, `ADS_DRDY` moved GPIO12→**GPIO22** and factory-reset moved GPIO13→**GPIO23** (both clean pins — no strap/USB/JTAG). Firmware defaults + comments, schematic (2 pins added to the ESP32 symbol; U11.4/U11.6 no-connects removed), and docs updated; `PROJECT_VER` → 1.1.3. Netlist re-verified: 393 pins / 75 nets / 0 mismatches.
- **BT1 & USB-C footprints resolved to KiCad-standard parts** (no custom draws): BT1 carrier → `Battery:BatteryHolder_Keystone_1042_1x18650` (exact ~78 mm dimensional match; populate with a Keystone 1042 or the LCSC MYOUNG BH-18650-B1BA002 C2988620 if terminals match), and the HRO USB-C footprint `Connector_USB:USB_C_Receptacle_HRO_TYPE-C-31-M-12` confirmed present in the standard library. Only the GDT land pattern remains, and it's gated (DNF, no MPN chosen yet).
- **All outstanding LCSC part numbers locked** (order-readiness): LM393 **C7955** (onsemi LM393DR2G, JLCPCB Basic), CN3791 **C154992** (Consonance — supersedes the earlier C124423 guess), DW01A **C351410** (PUOLOP, JLCPCB), FS8205A **C14212** (Fortune, JLCPCB), SMAJ10CA (D8/D14) **C320526** (LGE — was the unconfirmed C2836474), SMAJ13A (D11) **C110519** (Diodes Inc — C8057 stays unconfirmed). WellD's I²C bus — the ADS1115, i.e. the entire sensor ADC (level + battery) — was assigned to those pins and would have been unroutable. Moved to GPIO18/GPIO19 (both previously no-connects) across firmware Kconfig/sdkconfig, the schematic nets + R9/R10 pull-ups, and all docs. The custom ESP32 symbol's pin numbering was also confirmed wrong throughout; the official signal-pin map is now recorded for the symbol swap. Netlist re-verified: 391 pins / 75 nets / 0 mismatches.
- **Solar cold-charge cutoff added** (user decision, resolves #10f): LM393 comparator powered from the panel rail (zero battery draw at night), ratiometric NTC threshold (revived RT_SOLAR, thermally coupled to the cell), ≈+2 °C trip / ≈+4 °C release, clamping the CN3791 MPPT pin through an AO3400A so charge current backs off to zero when cold. Netlist re-verified: 391 pins / 75 nets / 0 mismatches.
- **Datasheet-verification pass over every 1S-conversion part** (blockers #10–#11): TP4056, HT7333-A, and DW01A confirmed as drawn (LCSC C16581 / C21583 / C351410-class); **two symbols were wrong and are corrected** — the CN3791 is a *controller*, not an integrated switch (external P-FET stage restored: SI2319CDS + SS34 series diode + 300 k gate resistor; COM compensation 220 nF+120 Ω added; verified pin map VG=1…DRV=10; I_CH = 120 mV/R_CS → 1.2 A at 0.1 Ω), and the FS8205A's real TSSOP-8 map is D=1&8/S1=2&3/G1=4/G2=5/S2=6&7 (redrawn). **The CN3791 has no TEMP pin → RT_SOLAR deleted; the solar path has no cold-charge cutoff** (new decision item #10f — RT1 guards only the USB path). Battery-carrier MPNs picked: MY-18650-02 THT clip pair (C2979182, recommended) or BH-18650-B1BA002 (C2988620). Netlist re-verified: 366 pins / 72 nets / 0 mismatches.

### Changed (1S conversion — firmware/converter side)
- Battery Kconfig defaults now match the 1S board: `CONFIG_WELLD_BATT_DIVIDER_RATIO` 430 → **200** (R7/R8 = 100 k/100 k), `CONFIG_WELLD_BATT_FULL_MV` 8400 → **4200**, `CONFIG_WELLD_BATT_EMPTY_MV` 6000 → **3000**. (No 2S boards were ever fabricated — no migration path is provided or needed.)
- The ADS1115 battery read (AIN2) now uses the **±4.096 V PGA** (since 1.2.0 the loop shunt read does too — see Fixed): the 1S ÷2 divider puts up to 2.1 V on AIN2, which the previous ±2.048 V range clipped exactly at full charge.
- Z2M converter battery defaults follow the firmware: `battery_full_mv`/`battery_empty_mv` defaults 8400/6000 → **4200/3000**, option range now 2500–4500 mV (1S). Converter tests rewritten for the 1S range (47 tests green).
- **Removed** `CONFIG_WELLD_USB_CHG_GPIO` and the GPIO4 charger-CE drive entirely: the TP4056 charges autonomously (CE strapped high in hardware) and GPIO4 has no schematic connection. GPIO4 is fully spare.

### Fixed
- OTA rollback can no longer flip a healthy image to the old slot during a coordinator outage: the boot-attempt counter is armed only while the running image is unproven (NVS marker `img_ok` stores the version string of the last image that completed a successful send), and low-battery-skip wakeups no longer count as failed boot attempts.
- An OTA download failure (stall abort, flash error) no longer counts as a Zigbee send failure when the sensor report itself was delivered — previously five OTA-plagued wakeups could wipe NVS and force a needless rejoin.
- `zigbee_send()` no longer deletes its synchronisation objects while `zb_task` may still be unwinding (>5 s teardown): the objects are deliberately leaked for the one remaining wake cycle instead (deep sleep resets the chip), eliminating a narrow use-after-free window.
- EP6 now reports the real device-side LQI, read from the Zigbee stack's neighbor table (parent entry). Previously it sent a constant 0 stub, which the converter suppresses as "unknown".
- OTA rollback guard was inert: it looked up `esp_ota_get_last_invalid_partition()`, which never matches in this app-level scheme. It now targets the inactive OTA slot (validated to contain an app image) and clears the RTC boot-attempt counter before restarting so the rolled-back image cannot immediately bounce back to the broken slot.
- OTA firmware version encoding now matches the documented `0xMMmmPP00` format used by the CI-packed `.zigbee` image (the firmware previously advertised `0xMMmm00PP`, so an identically-versioned OTA file looked like an upgrade).
- `zigbee_send()` no longer times out mid-OTA: it keeps waiting while a download is in progress instead of deleting the event group/timers still used by the Zigbee task and deep-sleeping with the radio active (the OTA stall watchdog still bounds the wait).
- Store-and-forward backlog is now burst-reported *before* the current reading, so Zigbee2MQTT's last-received state reflects the newest measurement instead of the oldest backlog entry.
- A low-battery wakeup now invalidates the rate-of-change history; previously the stale level was paired with a reset elapsed accumulator, producing a false rate spike on the first report after battery recovery. The low-battery threshold check is now at-or-below, as documented.
- Self-test VLOOP GPIO readback always failed (output-only pins read back 0); the input buffer is now enabled for the check.
- RTC event-log write index no longer wraps at 256 events (which made the log print as empty/short once per wrap).

### Changed
- Battery voltage is now reported over Zigbee (EP2) by default: the stale `CONFIG_WELLD_BATT_ADC_CHANNEL` int option (default `-1`, which silently disabled EP2 while the battery was still measured internally) is replaced by `CONFIG_WELLD_BATT_REPORT_ENABLED` (bool, default `y`).
- Z2M converter: the device-side LQI (EP6) is now exposed as `device_lqi` instead of `linkquality`, which Zigbee2MQTT's own coordinator-side key was shadowing. A value of 0 means "unknown" and is not published (firmware ≤ 1.0.2 always sent 0; this release populates the real reading — see Fixed).
- VLOOP (MT3608B EN) settling wait before a 4–20 mA read raised from 5 ms to 10 ms — the 12 V output caps now charge through the Q3 load-disconnect P-FET (PCB review 2026-07).
- The battery is now read before the water level and temperature so the low-battery guard can skip the remaining sensor reads entirely (no VLOOP boost power or DS18B20 NVS write on a wakeup that won't report).
- The post-send ACK window now scales with the store-and-forward backlog size (up to 4× `CONFIG_WELLD_ZIGBEE_SEND_DELAY_MS`), so a full 8-entry burst isn't cut off mid-flight.
- **Migration notes for the battery change**: (1) devices OTA-upgraded from ≤ 1.0.2 need a Zigbee2MQTT re-interview (or re-pair) to surface the new EP2 battery entities — Z2M caches the endpoint list from the original interview; (2) a stale `CONFIG_WELLD_BATT_ADC_CHANNEL` line in `sdkconfig.defaults.local` is silently ignored by Kconfig — operators who used `-1` to disable battery reporting must now set `CONFIG_WELLD_BATT_REPORT_ENABLED=n`.

## [1.0.0] – 2026-05-18

### Added
- Initial release: ESP32-C6 well-level monitor with 4–20 mA pressure transducer, DS18B20 temperature, ADS1115 battery monitoring.
- Zigbee 3.0 End Device reporting to Zigbee2MQTT.
- Adaptive sleep based on rate-of-change.
- OTA upgrade client with dual 1.5 MB app slots.
- Self-healing: 5 consecutive Zigbee send failures erase NVS and force rejoin.
- Host unit-test harness (Unity) and on-device test apps.
- Custom PCB design (80 × 55 mm) and OpenSCAD parametric enclosure.
